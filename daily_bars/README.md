# Дневные бары из минутных данных

`build_daily_bars.py` строит по одному дневному ряду для RTS и MIX из баз
минутного загрузчика. Нужен Python 3.10+; сторонние пакеты и сеть не требуются.
Исходные SQLite-файлы открываются только для чтения.

## Запуск

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe daily_bars\build_daily_bars.py

# Только RTS
.\.venv\Scripts\python.exe daily_bars\build_daily_bars.py --assets RTS

# Даты окончания баров, обе включительно
.\.venv\Scripts\python.exe daily_bars\build_daily_bars.py --start 2026-09-01 --end 2026-09-30

# Свои папки исходных и выходных баз
.\.venv\Scripts\python.exe daily_bars\build_daily_bars.py --input-dir C:\data_quote\m1_two_ticker --output-dir C:\data_quote\d1

.\.venv\Scripts\python.exe daily_bars\build_daily_bars.py --help
```

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `--input-dir` | Папка файлов `RTS_m1_two_ticker.db` и `MIX_m1_two_ticker.db` | `C:\data_quote\m1_two_ticker` |
| `--output-dir` | Папка файлов `RTS_d1.db` и `MIX_d1.db` | `data\d1` в корне проекта |
| `--assets` | Один либо оба актива: `RTS MIX` | Оба |
| `--start` | Первая дата **окончания** бара, включительно | Минимальная дата `LoadedDays` + 1 день |
| `--end` | Последняя дата **окончания** бара, включительно | Максимальная загруженная дата, не позже последней завершённой границы 21:00 МСК |

Результаты в `data/d1` исключены из Git. Вывод идёт в консоль, файловые
журналы не создаются. Коды завершения: `0` — успех, `1` — ошибка данных,
файлов или SQLite, `2` — неверные параметры, `130` — прерывание пользователем.
При ошибке одного актива второй обрабатывается независимо.

## Границы и переход между контрактами

Каждый интервал — **календарные сутки** `[21:00 предыдущей даты, 21:00 текущей
даты)` по Москве. Например, бар `TRADEDATE=2026-09-18` содержит минуты от
`2026-09-17 21:00:00` включительно до `2026-09-18 21:00:00` исключительно.
Минута в 21:00 относится уже к следующему бару. Интервалы не растягиваются
через выходные: пустые пропускаются, реальные сделки выходного дня учитываются.
Время хранится московское без суффикса часового пояса.

Для всего интервала выбирается ближайший по `(LSTTRADE, SECID)` контракт с
`LSTTRADE > TRADEDATE`. В исходных данных есть только дата экспирации:
в её день контракт завершает торги раньше 21:00, поэтому он не подходит
для интервала, заканчивающегося в 21:00 этой даты.

При экспирации `RIU6` 17 сентября:

| Дата бара | Интервал | Единственный тикер |
|---|---|---|
| 16 сентября | 15 сентября 21:00 — 16 сентября 21:00 | `RIU6` |
| 17 сентября | 16 сентября 21:00 — 17 сентября 21:00 | `RIZ6` |
| 18 сентября | 17 сентября 21:00 — 18 сентября 21:00 | `RIZ6` |

Следующий контракт используется **для всего бара**, включая предыдущий вечер.
Все запросы минут фильтруются по единственному `SECID`. Если выбранный
контракт не загружен, скрипт возвращает ошибку и не подменяет его дальней
серией. Цены контрактов не сдвигаются и не корректируются; между соседними
дневными барами возможен ценовой разрыв при смене серии.

## Полнота и повторный запуск

Перед расчётом проверяются актив, минутный интервал, часовой пояс и версия
исходной схемы. Для обеих календарных дат каждого интервала требуются
`LoadedDays` двух ближайших к экспирации серий, совпадение фактических
количеств минут и флагов пустого ответа. Это обнаруживает незагруженный день,
удалённые минуты и посторонние серии. SHA-256 исходных строк здесь заново
не вычисляется: проверку изменений цен и других полей выполняет минутный
загрузчик при повторном запуске.

Подтверждённый пустой ответ принимается как отсутствие минут. Отсутствие
сделок ровно в 21:00 и разрывы между минутами допустимы: первая и последняя
цены берутся из реально имеющихся минут. Искусственные свечи не добавляются.
Счётчики загрузки подтверждают сохранение полученного ответа, но не могут
обнаружить минуту, которую сам источник ISS не вернул.

Первая доступная дата `LoadedDays` без предыдущей даты не образует полный
интервал; вечер последней загруженной даты остаётся для следующего запуска.
Явно запрошенный интервал за пределами покрытия или до его завершения
отклоняется. Выходной файл создаётся после успешного расчёта актива.

При каждом запуске весь запрошенный период пересчитывается. Старые строки
этого периода заменяются одной транзакцией; строки за пределами периода
сохраняются. Если интервал стал пустым, его старая строка удаляется.
Ошибка вставки откатывает замену периода. Несовместимая выходная база
отклоняется. Повторный запуск не создаёт дублей.

## Таблицы SQLite

В `Daily` первичный ключ — `TRADEDATE`: на дату приходится не более одного
бара выбранного актива.

| Поле | Значение |
|---|---|
| `TRADEDATE` | Дата окончания интервала; отличается от календарной даты минуты в исходной базе |
| `SECID`, `SHORTNAME`, `LSTTRADE` | Единственный контракт, его название и дата экспирации |
| `BEGIN`, `END` | Фиксированные границы интервала; `END` исключён |
| `OPEN`, `CLOSE` | Open первой и Close последней минуты контракта |
| `HIGH`, `LOW` | Максимум High и минимум Low минут контракта |
| `VOLUME` | Сумма объёмов минут, в контрактах |
| `BODY` | `CLOSE - OPEN`; отрицательное тело у падающего бара |
| `UPPER_WICK` | `HIGH - max(OPEN, CLOSE)` |
| `LOWER_WICK` | `min(OPEN, CLOSE) - LOW` |
| `MINUTES` | Количество исходных минут выбранной серии |
| `FIRST_MINUTE`, `LAST_MINUTE` | Время начала первой и последней реально использованных минут |

Тело и фитили выражены в **пунктах котировки**, без пересчёта в деньги или
количество минимальных шагов цены. Разности считаются через десятичное
представление исходных цен и хранятся как `REAL`, как и сами цены.

В `Metadata` записаны актив, версия схемы, часовой пояс, интервал `D1`, граница
`DAY_START=21:00:00`, привязка даты `DATE_LABEL=END_DATE` и правило
`CONTRACT_SELECTION=LSTTRADE_GT_SESSION_END_DATE`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_daily_bars.py -v
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

Тесты используют базы в памяти и временные файлы только внутри `tests`.

Полные рабочие результаты можно независимо сверить с исходными минутами
(обе базы открываются только для чтения):

```powershell
.\.venv\Scripts\python.exe -X utf8 tests\verify_daily_databases.py
```
