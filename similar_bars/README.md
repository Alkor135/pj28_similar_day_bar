# Проверка идеи похожего дневного бара

`backtest_similar_bars.py` читает готовые дневные базы RTS/MIX из `data/d1`
только для чтения. Нужен Python 3.10+, сторонние пакеты и сеть не требуются.

## Алгоритм

1. После закрытия бара `t` рассматриваются ровно 20 предыдущих сохранённых
   баров: `t-20 .. t-1`. Размер окна меняется через `--lookback`.
2. Остаются только бары с тем же знаком `BODY`: рост, падение либо нулевое тело.
3. Для каждого признака — `abs(BODY)`, `UPPER_WICK`, `LOWER_WICK`, `VOLUME` —
   вычисляется `d(a,b) = abs(a-b) / max(a,b)`. При двух нулях `d=0`.
   Сравниваются относительные различия **размеров**, а не доли тела/фитилей
   в полном размахе свечи. У каждого признака свой ручной вес.
4. Расстояние — `sum(weight * d) / sum(weight)`. Выбирается минимум;
   при точном равенстве — более свежий аналог `j`.
5. Прогноз для `t+1` равен знаку `BODY[j+1]`. Бар `j+1` уже закрыт к моменту
   сигнала, даже если `j=t-1`: тогда `j+1=t`. Будущие бары при поиске аналога
   не используются; статистика всего ряда не используется для нормировки.
6. Результат в пунктах равен `prediction * BODY[t+1]`: плюс модуль тела при
   правильном направлении, минус при ошибочном. Затем результаты суммируются.

Первые `lookback` баров служат прогревом. Если полного окна ещё нет,
подходящего направления нет либо тело после аналога нулевое, сигнал
пропускается без изменения накопленного результата. Нулевое тело целевого
бара даёт ноль пунктов и учитывается отдельно от выигрышей/ошибок. Последний
доступный сигнал может иметь прогноз, но пока не иметь результата (`pending`).
Для текущего бара с нулевым телом ищутся только прошлые нулевые тела.

Следующий бар — следующая строка `Daily`, даже если между датами выходные.
Календарные пустые интервалы искусственно не заполняются. Контракты и
интервалы 21:00–21:00 берутся из дневной базы без изменения. При смене серии
сравниваются те же признаки; отдельного фильтра по контракту нет.

## Запуск и ручные веса

Из корня проекта:

```powershell
# Оба актива с равными весами, сигналы с марта 2020 года
.\.venv\Scripts\python.exe similar_bars\backtest_similar_bars.py --start 2020-03-01

# Тело вдвое важнее каждого фитиля, объём с весом 0.5
.\.venv\Scripts\python.exe similar_bars\backtest_similar_bars.py --start 2020-03-01 --body-weight 2 --upper-wick-weight 1 --lower-wick-weight 1 --volume-weight 0.5

# Полностью исключить объём
.\.venv\Scripts\python.exe similar_bars\backtest_similar_bars.py --start 2020-03-01 --volume-weight 0

# Только RTS, иной период и окно; отдельная папка сохраняет прежний эксперимент
.\.venv\Scripts\python.exe similar_bars\backtest_similar_bars.py --assets RTS --start 2020-03-01 --end 2020-12-31 --lookback 40 --output-dir data\experiment

.\.venv\Scripts\python.exe similar_bars\backtest_similar_bars.py --help
```

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `--input-dir` | Папка `<ASSET>_d1.db` | `data/d1` в корне проекта |
| `--output-dir` | Папка CSV и JSON | `data/similar_bars` в корне проекта |
| `--assets` | Один либо оба актива | `RTS MIX` |
| `--lookback` | Число предыдущих баров, целое ≥ 1 | `20` |
| `--start`, `--end` | Даты **сигналов**, обе включительно | Весь ряд |
| `--body-weight` | Вес модуля тела | `1` |
| `--upper-wick-weight` | Вес верхнего фитиля | `1` |
| `--lower-wick-weight` | Вес нижнего фитиля | `1` |
| `--volume-weight` | Вес объёма | `1` |

Все веса должны быть конечными и неотрицательными; хотя бы один — больше
нуля. Вес `0` исключает признак. Значимы отношения весов: `2,2,2,2`
эквивалентны `1,1,1,1`. У направления нет мягкого веса: одинаковый знак
тела остаётся обязательным условием.

`--start` не отрезает предысторию для поиска. Если заданной даты в базе нет,
начинается с первого доступного бара после неё. `--end` ограничивает дату
сигнала; следующий бар после неё учитывается для результата, если есть в
базе. Поэтому последний результат может иметь дату позже `--end`.

## Результаты

В консоль выводятся число сделок, выигрышей, ошибок, нулевых тел, точность,
сумма пунктов и максимальная просадка. Файловые журналы не создаются.

Для каждого актива сохраняются файлы с постоянными именами:

- `<ASSET>_trades.csv`: каждый сигнал, включая пропуски и ожидающий прогноз;
  UTF-8 BOM, разделитель `;`. Есть признаки текущего и выбранного баров,
  расстояние, число кандидатов, дата и тело бара после аналога, прогноз,
  целевой бар, результат, накопленные пункты и текущая просадка.
- `<ASSET>_summary.json`: путь источника, окно, четыре фактических веса,
  запрошенные и реальные границы, счётчики, итог, точность и максимальная
  просадка. `accuracy_percent = 100 * hits / (hits + misses)`; целевые
  нулевые тела исключены из знаменателя. Если знаменатель нулевой,
  точность равна `null`. `gross_loss_points` — положительный модуль убытков;
  `profit_factor = gross_profit_points / gross_loss_points`, либо `null`
  при отсутствии убытков. `always_long_points` и `always_short_points`
  показывают сумму тел при постоянном направлении на тех же оценённых барах.

`prediction` и `actual_direction`: `1` вверх, `-1` вниз, `0` нулевое тело.
Пустое поле означает отсутствие значения. `correct` равно `True`/`False`
только для оценённого ненулевого целевого тела; иначе поле пустое.

| `status` в CSV | Значение |
|---|---|
| `evaluated` | Прогноз ±1 оценён по следующему бару |
| `insufficient_history` | Ещё нет полного окна |
| `no_matching_direction` | В окне нет бара нужного направления |
| `flat_prediction` | Тело бара после аналога равно нулю, сделка пропущена |
| `pending` | Прогноз ±1 есть, следующий бар ещё отсутствует |

Накопленный результат начинается с нуля. Просадка — разница между
максимальным достигнутым результатом (включая исходный ноль) и текущим.
Повторный запуск заменяет оба файла актива; каждый файл заменяется атомарно,
но общей транзакции между CSV и JSON нет. При необходимости сохранить другой
эксперимент укажите отдельный `--output-dir`. Исходные базы не изменяются.

Это расчёт суммы тел в пунктах котировки: вход по Open следующего бара и
выход по его Close без комиссий и проскальзывания. Разрыв от Close текущего
до Open следующего бара не входит в результат. Движение внутри свечи,
внутридневная просадка, обеспечение и стоимость пункта не моделируются.

Коды завершения: `0` — успех, `1` — ошибка данных/файлов, `2` — ошибка
параметров, `130` — прерывание. Ошибка одного актива не мешает проверке другого.

## Автономный HTML-отчёт

`build_pnl_report.py` создаёт один HTML-файл с графиками накопленного PnL,
просадки и таблицей показателей из готовых `<ASSET>_trades.csv` и
`<ASSET>_summary.json`. Результат каждого прогноза показан на дате **целевого
бара**, начальная точка равна нулю, между закрытиями PnL сохраняется.

```powershell
# Сначала расчёт с нужными весами, затем отчёт
.\.venv\Scripts\python.exe similar_bars\backtest_similar_bars.py --start 2020-03-01 --body-weight 2 --volume-weight 0.5
.\.venv\Scripts\python.exe similar_bars\build_pnl_report.py

# Отчёт только по RTS
.\.venv\Scripts\python.exe similar_bars\build_pnl_report.py --assets RTS

# Результаты другого эксперимента и своё имя файла
.\.venv\Scripts\python.exe similar_bars\build_pnl_report.py --input-dir data\experiment --output data\experiment\report.html --title "Мой эксперимент"

.\.venv\Scripts\python.exe similar_bars\build_pnl_report.py --help
```

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `--input-dir` | Папка готовых CSV/JSON | `data/similar_bars` в корне проекта |
| `--assets` | Активы отчёта | `RTS MIX` |
| `--output` | Путь HTML-файла | `pnl_report.html` в папке `--input-dir` |
| `--title` | Заголовок отчёта | `Похожие дневные бары: PnL` |

Файл `data/similar_bars/pnl_report.html` можно открыть двойным щелчком,
перенести на другой компьютер или отправить отдельно: внутри находятся все
данные, стили и код. Интернет, внешние библиотеки и соседние файлы для
просмотра не нужны. При создании отчёта используется расположенный рядом
со скриптом `pnl_report_template.html`; Python и шаблон нужны только для
генерации, а не просмотра готового файла.

Наведение или касание показывает значения по датам; кнопки RTS/MIX управляют
видимостью линий. При переходе между графиками прежняя направляющая очищается.
Таблица содержит итог, число и точность прогнозов,
прибыль-фактор, суммы и средние выигрыши/проигрыши, средний результат,
лучший/худший прогноз, максимальную просадку, отношение итога к просадке,
максимальную серию убытков, число пропусков и ожидающих прогнозов.
Веса и период автоматически берутся из каждого JSON; вручную повторять их
в параметрах отчёта не нужно. Показатели без знаменателя обозначены тире.

Генератор сверяет CSV и JSON по итогам, просадке, границам и счётчикам,
проверяет даты и результаты сделок. Дробные накопленные суммы сверяются
с учётом сохранения чисел как `float`, без произвольного числового допуска.
При расхождении файлов возвращает
ошибку. Исходники открываются только для чтения; прежний HTML заменяется
атомарно только после успешной проверки всех выбранных активов. Повторный
запуск перезаписывает тот же файл. Логи не создаются. Коды завершения:
`0` — успех, `1` — ошибка данных/файлов, `2` — ошибка параметров,
`130` — прерывание. Для повторного построения после смены весов сначала
запустите расчёт стратегии, затем генератор отчёта.
