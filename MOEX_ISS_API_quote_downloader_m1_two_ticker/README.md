# Минутные свечи двух ближайших фьючерсов RTS и MIX

`update_futures_m1_two_ticker.py` загружает по два ближайших к экспирации
контракта каждого актива: две серии RTS и две серии MIX. За основу взяты
выбор исторической пары, SQLite и докачка из
`C:\Users\Alkor\VSCode\quote_download\MOEX_ISS_API_quote_downloader_day2`.
Используется стандартная библиотека Python 3.10+, сторонние пакеты не нужны.

## Запуск

Команды выполняются из корня проекта `C:\Users\Alkor\VSCode\pj28_similar_day_bar`:

```powershell
.\.venv\Scripts\python.exe MOEX_ISS_API_quote_downloader_m1_two_ticker\update_futures_m1_two_ticker.py
```

По умолчанию загружаются оба актива с **2026-09-01 по вчерашнюю московскую
дату включительно**. Начало соответствует константе `FIRST_DATE` в коде
загрузчика-образца; его README упоминает другую дату. Более ранний период
можно задать через `--start`; доступность конкретных свечей зависит от ISS.
Текущий календарный день не загружается даже при явном `--end`.

Базы и папка создаются автоматически:

| Актив ISS | Коды контрактов | SQLite-база по умолчанию |
|---|---|---|
| RTS | RI… | `C:\data_quote\m1_two_ticker\RTS_m1_two_ticker.db` |
| MIX | MX… | `C:\data_quote\m1_two_ticker\MIX_m1_two_ticker.db` |

Другие варианты запуска:

```powershell
# Оба актива за заданный период
.\.venv\Scripts\python.exe MOEX_ISS_API_quote_downloader_m1_two_ticker\update_futures_m1_two_ticker.py --start 2026-09-01 --end 2026-09-30

# Только RTS или только MIX
.\.venv\Scripts\python.exe MOEX_ISS_API_quote_downloader_m1_two_ticker\update_futures_m1_two_ticker.py --assets RTS
.\.venv\Scripts\python.exe MOEX_ISS_API_quote_downloader_m1_two_ticker\update_futures_m1_two_ticker.py --assets MIX

# Параметры сети и папка баз
.\.venv\Scripts\python.exe MOEX_ISS_API_quote_downloader_m1_two_ticker\update_futures_m1_two_ticker.py --data-dir C:\data_quote\m1_two_ticker --timeout 30 --retries 5 --pause 0.1

# Перезагрузка периода, включая уже сохранённые даты
.\.venv\Scripts\python.exe MOEX_ISS_API_quote_downloader_m1_two_ticker\update_futures_m1_two_ticker.py --start 2026-09-01 --end 2026-09-30 --recheck

# Повторная проверка подтверждённых пустых выходных
.\.venv\Scripts\python.exe MOEX_ISS_API_quote_downloader_m1_two_ticker\update_futures_m1_two_ticker.py --recheck-empty-weekends

# Справка
.\.venv\Scripts\python.exe MOEX_ISS_API_quote_downloader_m1_two_ticker\update_futures_m1_two_ticker.py --help
```

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `--start` | Первая календарная дата, `ГГГГ-ММ-ДД`, включительно | `2026-09-01` |
| `--end` | Последняя календарная дата включительно, не позже вчера по Москве | Вчера по Москве |
| `--assets` | Один или оба базовых актива: `RTS MIX` | Оба |
| `--data-dir` | Папка отдельных SQLite-баз | `C:\data_quote\m1_two_ticker` |
| `--timeout` | Положительный тайм-аут запроса, секунд | `20` |
| `--retries` | Число попыток запроса, включая первую | `4` |
| `--pause` | Пауза после успешного запроса, секунд | `0.05` |
| `--recheck` | Заново запросить все даты периода | Выключен |
| `--recheck-empty-weekends` | Заново запросить подтверждённые пустые выходные | Выключен |

## Логика загрузки

1. Для каждой календарной даты и каждого актива читаются все страницы
   `/iss/history/engines/futures/markets/forts/securities.json`.
   Учитываются отдельные фьючерсы на доске `RFUD`. Спреды, чей `SECID` состоит
   из двух кодов контрактов одного актива, исключаются после чтения всех страниц.
   Неизвестные строки с пустым `ASSETCODE` считаются ошибкой. При пустой истории
   состав контрактов ищется сначала в предыдущих 14 календарных днях,
   затем в следующих 14 завершённых днях. Ответы истории кешируются в памяти.
   Если две действующие серии определить не удалось, дата остаётся ошибочной;
   пустота минутных данных не предполагается.
2. Из `/iss/securities/{SECID}.json` берутся реальные `SHORTNAME` и `LSTTRADE`.
   Описания сохраняются в `Contracts`. Архивные коды вроде `RIH8_2018`
   передаются и хранятся целиком.
3. Выбираются две серии с минимальными `LSTTRADE >= проверяемая дата`;
   при одинаковой экспирации порядок определяется `SECID`. Последний день
   торгов включается. Недоступная ближняя серия не подменяется дальней.
4. Через `/iss/engines/futures/markets/forts/boards/RFUD/securities/{SECID}/candles.json`
   запрашиваются свечи `interval=1`, `from=ГГГГ-ММ-ДД 00:00:00`,
   `till=ГГГГ-ММ-ДД 23:59:59`. Чтение продолжается до пустой страницы;
   фиксированное количество строк или минут за день не предполагается.
   См. [документацию MOEX по свечам фьючерсов](https://moexalgo.github.io/docs/api/get-futures-candles/).
5. Проверяются поля и структура ответа, конечность чисел, границы OHLC,
   целый неотрицательный объём, минутные временные границы и отсутствие дублей.
   Только после получения обеих серий их свечи и две отметки `LoadedDays`
   сохраняются одной транзакцией. При ошибке прежний день сохраняется целиком.

Время `BEGIN` и `END` хранится в московском времени без суффикса часового
пояса. `TRADEDATE` в этой базе — **календарная дата начала минутной свечи**.
Это не попытка приписать вечернюю сессию следующему биржевому дню. Состав
контрактов берётся из доступной истории, а их экспирации проверяются именно
на календарную дату свечей. Предыдущая историческая дата имеет приоритет
над следующей, чтобы не выбирать новые серии, появившиеся позднее.

У MOEX [сессии выходного дня относятся к следующему торговому дню](https://www.moex.com/ru/derivatives/weekend-session).
Поэтому отсутствие дневной строки за субботу или воскресенье не позволяет
пропустить запрос минутных свечей за эти даты.

Нестандартные дневные свечи, например с 21:00 до 21:00 следующего торгового
дня, здесь ещё не формируются. Минутные записи сохраняют исходные времена
для последующей агрегации.

## Пропуски и повторный запуск

При каждом запуске перебирается весь заданный период. День пропускается,
только если в `LoadedDays` есть две отметки, обе серии непустые,
фактическое количество свечей
совпадает с сохранённым, отсутствуют посторонние серии и совпадают SHA-256
всех сохранённых полей. Удалённые строки и изменённые значения вызывают
повторную загрузку дня.

Разрывы между минутами допускаются: искусственные свечи не создаются.
Корректный пустой ответ `candles` сохраняется как `EMPTY_RESPONSE=1`, без
выдуманных котировок. Если хотя бы одна серия пустая, дата проверяется
снова при следующем запуске. Исключение — кеш пустых выходных ниже.
Дневной `NUMTRADES` не подтверждает наличие сделок в конкретную календарную
дату: торговый день может включать сессии выходных.
Если ранее для серии уже были реальные свечи, новый пустой ответ считается
ошибкой; прежняя пара сохраняется целиком.
Контрольная сумма подтверждает целостность локальной
записи полученного ответа; отсутствие отдельных свечей в самом ISS она
обнаружить не может.

Перебираются и выходные. Только после успешных пустых ответов `candles`
**обеих выбранных серий** за субботу или воскресенье дата сохраняется
в `EmptyWeekends` одной транзакцией с двумя отметками `LoadedDays`.
При использовании кеша также проверяются отметки и контрольные суммы.
Пустые будни не пропускаются. Сетевой отказ, неверная структура и неполная пагинация не
считаются отсутствием торгов. Для обнаружения поздних публикаций ISS
используйте `--recheck` или `--recheck-empty-weekends` в нужном периоде.

## Таблицы SQLite

`Minute` содержит:

| Поля | Содержимое |
|---|---|
| `TRADEDATE`, `SECID` | Календарная дата и полный код контракта |
| `BEGIN`, `END` | Начало и конец минутной свечи по Москве |
| `OPEN`, `LOW`, `HIGH`, `CLOSE` | Цены OHLC |
| `VOLUME`, `VALUE` | Объём в контрактах и оборот из ISS |
| `SHORTNAME`, `LSTTRADE` | Название контракта и последняя дата торгов |

Первичный ключ — `(BEGIN, SECID)`. Индексы поддерживают выборку по дате
и по контракту/времени. Минутного `OPENPOSITION` в обычном ответе `candles`
нет, поэтому он не подставляется из дневной истории.

Служебные таблицы: `Contracts` — кеш описаний, `LoadedDays` — количество
и контрольная сумма каждой серии за день, а также флаг `EMPTY_RESPONSE`,
`EmptyWeekends` — подтверждённые
пустые выходные, `Metadata` — актив, интервал, часовой пояс и версия схемы.
Запись MIX в базу RTS и использование несовместимой схемы запрещены.

## Журналы, ошибки и проверки

Журналы UTF-8 находятся только в `logs` корня проекта:
`logs\m1_two_ticker.log` и `logs\m1_two_ticker_errors.log`.
При запуске оба перезаписываются. При достижении 5 МиБ файл очищается
и запись продолжается с начала без архивов.

Сетевые запросы повторяются с возрастающими паузами. При исчерпании попыток
загрузка текущего актива останавливается; второй актив всё равно проверяется.
Ранее записанные дни остаются в базе. Следующий запуск докачает пропуски.
Коды завершения: `0` — нет известных ошибок, `1` — сетевой отказ, неполные
данные или ошибка БД, `130` — прерывание пользователем. Пустые календарные
выборки остаются для будущей проверки и сами по себе не означают ошибку.

Проверочный запуск 21.10.2026 создал обе базы в указанной папке, но запросы
ISS для RTS и MIX завершились тайм-аутом до получения истории. Котировки
при этом не были загружены. При доступном ISS повторите обычную команду.
